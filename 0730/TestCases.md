# 系統測試案例與執行紀錄

本測試紀錄涵蓋一般功能測試、邊界條件測試及錯誤處理驗證。

| 案例編號 | 測試案例說明 | 操作步驟 / 輸入資料 | 預期結果 | 實際結果 | 測試狀態 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **TC01** | 一般正式報名 | 輸入 R101, Alice | 成功加入主資料，顯示正式報名成功 | 與預期一致 | 通過 |
| **TC02** | 報名達到容量上限 | 容量為 2，輸入第 3 筆 R103 | 進入候補 Queue，顯示進入候補佇列 | 與預期一致 | 通過 |
| **TC03** | 報名重複編號 | 已有 R101，再次輸入 R101 | 系統拒絕新增，提示編號重複 | 與預期一致 | 通過 |
| **TC04** | 二分搜尋已存在 ID | 搜尋已排序陣列中的 R102 | 成功回傳對應物件索引或提示存在 | 與預期一致 | 通過 |
| **TC05** | 二分搜尋不存在 ID | 搜尋 R999 | 回傳 -1，提示找不到 | 與預期一致 | 通過 |
| **TC06** | 空陣列二分搜尋 | 傳入空陣列與 ID "R101" | 回傳 -1，系統不崩潰 | 與預期一致 | 通過 |
| **TC07** | 取消報名並觸發候補補上 | 取消 R101（此時候補有 R103） | R101 移至 Stack，R103 從 Queue 補至主資料 | 與預期一致 | 通過 |
| **TC08** | 取消不存在的 ID | 取消 R999 | 提示找不到欲取消資料，狀態維持原樣 | 與預期一致 | 通過 |
| **TC09** | 復原取消操作 | 執行 undoCancel() | 從 Stack 推出 R101 並重新放回主資料 | 與預期一致 | 通過 |
| **TC10** | 空 Stack 執行復原 | 對空的 Stack 執行 undoCancel() | 提示沒有可復原的紀錄，程式不當機 | 與預期一致 | 通過 |
| **TC11** | Merge Sort 空陣列 | 傳入長度為 0 的陣列 | 立即 return，不觸發陣列越界異常 | 與預期一致 | 通過 |
| **TC12** | Merge Sort 單筆資料 | 傳入長度為 1 的陣列 | 不進行拆分，維持原樣輸出 | 與預期一致 | 通過 |
| **TC13** | Merge Sort 完全反向資料 | 傳入 [R103, R102, R101] | 正確排序為 [R101, R102, R103] | 與預期一致 | 通過 |
| **TC14** | 順序穩定性測試 | 依優先度排序同權重的維修任務 | 相同優先度的任務保留原本的輸入順序 | 與預期一致 | 通過 |
| **TC15** | 順向搜尋不符大小寫 | 搜尋名稱 "alice"（小寫） | 忽略大小寫，成功尋獲 Alice | 與預期一致 | 通過 |
